# 적산 업무에서 출발한 AI 협업 시스템

이 프로젝트는 건설 실무자가 요청한 공사를 **근거를 확인할 수 있는 물량·단가·금액과 문서 수정 결과로 연결**하기 위해 만든 로컬 업무 도구다. 자연어 요청은 Codex가 해석하고, 계산과 자료 적용은 명시된 규칙과 검증 절차를 따른다. 공개 저장소는 실제 현장 자료를 제외한 코드와 합성 예제로 이 구조를 설명한다.

## 적산은 무엇을 계산하는가

적산은 공사를 구성하는 작업을 나누고, 필요한 수량을 구한 뒤, 단위당 비용을 적용하여 공사비를 산출하는 업무다. 이름이 비슷한 항목을 찾아 가격을 곱하는 것만으로는 충분하지 않다. 같은 합판도 두께·등급·단위·공급 조건이 다르면 적용할 수 있는 가격이 달라진다.

| 용어 | 이 프로젝트에서 다루는 의미 |
|---|---|
| 공종 | 합판 설치, 포장, 배관 등 공사를 이루는 작업 |
| 물량 | 해당 작업의 면적·체적·길이·개수 등 |
| 일위대가 | 작업 기준수량 1단위에 필요한 재료비·노무비·경비의 산출 내역 |
| 내역서 | 공종·규격·단위·수량·단가·금액과 집계를 담는 문서 |
| 품셈 | 일정 조건의 작업에 필요한 인력·장비·재료 등을 산정하는 기준 |
| 직접공사비 | 선택한 작업에 직접 드는 재료비·노무비·경비 |
| 전체 도급액 | 직접공사비와 원문에 연결된 제경비·이윤·세금 등을 포함하는 별도의 집계 범위 |

예를 들어 합판 공급가격이 1㎡당 얼마인지 확인해도 설치 일위대가는 바로 나오지 않는다. 절단 손실, 고정재, 작업 인력, 생산성, 공구경비, 현장 조건을 각각 확인해야 한다. [내수합판 사례](case-study.md)는 확인한 값과 추정한 조건을 구분한 예다.

## 해결하려는 문제와 사용자

주 사용자는 Excel 내역서와 PDF·CAD 도면을 오가며 공사비를 검토하는 실무자다. 기존 문서에는 설계·착공·변경 판본, 총괄·연차, 건축·토목·설비 항목이 섞여 있을 수 있다. 공종 하나를 추가해도 다른 시트의 소계와 상위 집계가 함께 바뀌어야 한다.

이 환경에서 중요한 요구는 다음과 같다.

- 공종 이름뿐 아니라 현장·판본·규격·단위·포함 범위를 맞춘다.
- 계산에 사용한 숫자가 어느 파일과 위치에서 왔는지 남긴다.
- 독립 외부가격과 내역서에 저장되어 있던 가격을 구별한다.
- 근거가 부족한 값은 미확정으로 드러내고 확정 합계처럼 표시하지 않는다.
- 원본을 보존하면서 수정본과 변경 전후 기록을 만든다.
- 저장한 Excel 수식과 실제 Excel 재계산 결과를 대조한다.

## 요청에서 결과까지

1. **대상 특정:** 현장, 문서 판본, 공사 부서, 총괄·연차, 실제 행을 정한다.
2. **공사 구성:** 등록된 공종 관계에서 후보와 필수 조건, 제외 범위를 검토한다.
3. **물량 산출:** 근거가 있는 직접 수량, 치수 산식, 명시된 도면 수치를 연결한다.
4. **가격 선택:** 독립 DB와 공식 API에서 규격·날짜·단위·세금·납품 범위가 맞는 가격을 확인한다.
5. **계산:** Decimal과 명시된 절사 규칙으로 비목별 단가와 금액을 산출한다.
6. **문서 반영:** 요청한 대상에 한해 새 Excel 사본을 수정하고 연결 집계를 확인한다.
7. **검증·기록:** 독립 계산, 저장 수식, 별도 사본의 Excel 재계산, 원본 SHA256을 비교한다.

각 단계의 산출물은 JSON 요청·계산근거·변경계획·검증 보고서로 이어진다. 사람이 다시 검토할 때 계산 결과에서 사용한 자료로 거슬러 올라갈 수 있게 하는 구조다.

## 공급가격과 설치가격

외부가격의 의미는 공급처별로 다르다. 시설자재 공표가격은 참고가격이고, 쇼핑몰 가격은 해당 계약과 납품 조건의 구매가격이다. 물품목록은 규격 확인용 메타데이터이며, 연료 평균가격은 장비의 시간당 운전비와 다르다.

시스템은 공급가격을 설치 공종 전체 단가로 바꾸지 않는다. 설치가 포함된 상품가격을 재료비로만 분리하거나, 기계 구매가격을 시간당 장비비로 적용하는 것도 제한한다. 단위와 포장 수량, 부가세 포함 여부, 운반 조건을 확인한 매핑이 있어야 계산에 연결한다.

## 총괄·연차와 여러 시트의 관계

같은 공종이 총괄, 1차 연도, 다음 연도에 별도 행으로 존재할 수 있다. 총괄 물량이 620㎡라고 해서 각 연차에 모두 620㎡를 넣으면 중복 계상이 된다. 어느 연도에 반영할지 먼저 정하고, 총괄과 연차 합계의 관계를 확인해야 한다.

행이 숨겨져 있거나 특정 연차만 표시되는 내역서도 있다. 숫자가 반영되었는지 판단할 때 현재 보이는 행뿐 아니라 실제 연결 수식과 집계 위치까지 확인해야 한다. 이 문제 때문에 시스템은 단순 파일 저장과 연결 집계 검증을 별도 단계로 둔다.

## 미확정 상태를 결과로 다루기

단가가 없거나 도면과 산출서가 충돌하면 그 값을 0원으로 채우지 않는다. 계산 가능한 부분합과 미확정 항목을 구분하고, 필요한 자료와 막힌 이유를 남긴다. 자료가 충돌한 구성요소만 미완성으로 둘 수 있어 다른 검토는 계속할 수 있다.

`known_subtotal`은 확인된 항목의 부분합이다. 전체 금액이 완성되었다는 뜻이 아니다. 직접공사비 검증이 통과해도 보험·제경비·이윤·부가세 연결 전체를 검증하지 않았다면 전체 도급액 완료로 보고하지 않는다.

## AI와 사람이 맡는 역할

사용자는 현장 요구, 추가 공사의 범위, 필요한 결과, 추정을 허용할 조건과 검증 기준을 정의한다. Codex는 구현 보조와 요청 구조화, 자료 조회, 코드·계산 실행, 문서 작성과 검증 절차 수행을 돕는다. 세부 수치의 산술은 Python 규칙과 Decimal 계산기가 처리한다.

현재 코드에는 모델 학습이나 별도 LLM 추론 서버, 임베딩 검색 서비스를 구현하지 않았다. 이 프로젝트의 AI 요소는 **기존 적산 도구를 호출하고 근거와 검증을 연결하는 협업 흐름**이다. 사용자와 Codex의 개별 코드 기여율이나 업무시간 절감률은 측정하지 않았다.

후보 일치나 자동 검사 통과가 현장 적합성과 승인까지 대신하지는 않는다. 지붕 경사·고소 작업·양중 조건처럼 추가 판단이 필요한 사항은 기록으로 남긴다.

## 공개 저장소의 범위

실제 현장명, 계약 내역서, 도면, 원본 DB, API 인증정보, 공급사 상세, 원문 저작물은 공개 패키지에 포함하지 않는다. 공개 데모는 합성 자료로 계산 경로와 실패 조건을 확인하는 데 목적이 있다. 로컬 시스템에서 과거에 기록한 검증은 [검증 문서](validation.md)에서 이번 공개 데모와 구분한다.
