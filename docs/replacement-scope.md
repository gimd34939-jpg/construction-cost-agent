# 어떤 프로그램과 업무를 대체하려 했는가

## 소규모 업체의 작은 작업에서 출발

개발 배경은 소규모 업체가 몇 개 공종의 견적·추가·부분 변경을 처리하는 데에도 전문 적산 프로그램의 도입·유지 비용, 학습과 자료 입력 부담을 감당해야 한다는 문제의식이다. 작은 작업 규모와 사용 빈도에 비해 도구를 운영하는 비용이 크다면 비효율적이라고 보았다.

대신 필요한 품셈과 가격자료를 직접 데이터베이스로 만들고, AI가 이 데이터를 조회하며 계산·문서 도구를 실행하도록 구성했다. 사용자는 원하는 공사와 조건을 자연어로 설명하고, 시스템은 근거를 연결한 산출 결과와 검토 가능한 문서를 만든다.

이것은 실제 구매비·구독료·절감률을 측정한 시장조사 결과가 아니라 사용자가 설명한 개발 동기다. 가격표를 조사하지 않은 제품의 비용을 임의로 적거나, 기존 프로그램을 모두 고가라고 일반화하지 않는다.

## 비교 대상이 되는 전문 적산 프로그램

| 대표 제품 | 공식 자료에서 확인되는 역할 | 이 프로젝트와 겹치는 업무 |
|---|---|---|
| [글로텍 EBS](https://www.glotechsoft.com/ebs) | 기초단가·일위대가·직접/간접공사비 내역서와 Excel 연계 | 자원 가격 연결, 일위대가 구성, 내역서 작성·부분 수정 |
| [다산소프트 EST / EST+3](https://www.dasansoft.com/) | EST 프로그램 유지보수·업그레이드, 데이터와 일위대가 자료 제공 | 적산 자료 조회·적용과 일위대가·내역 작성 업무 |

제품 역할의 공식 페이지 확인일은 2026-10-25다. 여기서 EBS·EST는 **업무상 비교 대상**이다. 사용자가 실제로 어느 제품을 사용하다 해지했는지, 특정 제품 전체를 이 시스템으로 교체했는지까지 확인한 기록은 없다. ESTX 형식의 자료가 있다는 이유만으로 특정 회사의 제품 사용 이력이나 완전 호환성을 단정하지 않는다.

## 이번 시스템의 대체 범위

| 기존에 사람이 수행하는 작업 | 데이터 + AI로 구성한 처리 방식 | 현재 경계 |
|---|---|---|
| 품셈책과 단가자료에서 항목 찾기 | 공종·규격·조건·원문 위치가 연결된 DB 조회 | 자료 수록과 해당 현장 적합성은 별도 확인 |
| 재료·노무·장비 가격을 골라 입력 | 독립 가격자료와 공식 API를 조회하고 자원에 매핑 | 규격·기간·포함범위가 맞아야 적용 |
| 일위대가와 산식 직접 입력 | 검증된 계수·명시 산식을 계산기로 실행 | 미지원 산식과 현장 계수는 별도 검토 |
| Excel 내역서에 공종 추가·단가 수정 | 지정한 행의 새 사본 편집, 연결 소계와 집계 추적 | 지원되는 수식·파일 구조에 한정 |
| 계산 결과와 원본을 수기로 대조 | 독립 계산·저장 수식·별도 Excel 재계산·SHA 비교 | 검증한 셀·공종 범위에서 완료 판정 |

목표는 **소규모 공사의 선택한 적산 업무를 AI로 수행할 수 있게 하는 것**이다. 전문 제품의 전체 내역관리, 발주처 전용 제출 포맷, 전 공종 자동 산출, 모든 제경비와 계약 검증을 한 번에 대체했다고 주장하지 않는다. Excel은 결과 검토와 재계산에, CAD는 필요한 도면 작업에 계속 활용한다.

## 비용과 작업 방식에서 기대한 변화

자료를 매번 찾아 옮겨 적는 대신 축적된 DB를 재사용하고, 적산 프로그램의 화면과 메뉴를 직접 조작하는 작업 일부를 자연어 요청과 검증 가능한 도구 실행으로 바꾸려 했다. 소규모 작업에 맞는 범위로 필요한 기능을 구성하는 것이 설계 방향이다.

AI 이용, 데이터 유지·검수, API 관리, 필요한 Office·CAD 환경에도 비용과 노력이 든다. 따라서 전체 비용이 0원이라거나 실제 절감액이 이미 확인되었다고 설명하지 않는다. 다음 단계에서는 같은 소규모 작업을 수동 방식과 비교해 시간·재작업률·총 운영비를 측정할 계획이다.
