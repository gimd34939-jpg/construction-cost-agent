# 검증 범위와 한계

이 문서는 **로컬 시스템에 남아 있는 과거 검증 기록**과 **공개 저장소에서 실행하는 합성 데모 검증**을 구분한다. 과거 기록은 2026-10-06 실행본을 조사해 요약했다. 원본 보고서와 현장자료는 공개 저장소에 복사하지 않는다.

## 로컬 실행본에 기록된 검증

아래 수치는 과거 해당 버전과 조건의 기록이다. 이번 포트폴리오 작성 과정에서 같은 API 전량 수집이나 실제 Excel 검증을 다시 수행했다는 의미가 아니다.

| 범위 | 기록된 결과 | 무엇을 확인했는가 |
|---|---:|---|
| 2026 표준품셈 구조화 | PDF 982쪽, 1,095공종·5,987변형·11,850활성투입 | 전편 원문을 공종·규격·자원·원문 위치로 연결한 수록 범위 |
| 품셈 고정계수 독립 대조 | 2,556변형·4,539투입 | 계산 지원 대상으로 분류한 계수·기준량·단위·원문 행의 대응 |
| 명시 산식 실행기 | 50레코드, 시험27건 통과 | 등록된 산식의 산술·입력 경계·금지 AST 거부. 전 산식 완전 검증과 구별 |
| 시설공통자재 파일 독립 대조 | 406,098행, 불일치 0 | 수입 데이터와 원문 필드·행 위치·가격·날짜·세금·삭제 값의 대응 |
| 외부가격 원장 시험 | 29건 통과 | 삭제 최신판본, 누락·충돌, 범위, 시험자료 분리, 원문 보존 |
| API 계약 시험 | 33건 통과 | JSON/XML, 페이지 완결성, 오류와 키 숨김, 조회조건·operation 유지 |
| 계산·가격정책 시험 | 70건 통과 | 기존 가격 기본 차단, 출처 재포장, 세금·포장·단위·규격, 과거 결과 재생 |
| 보존 검사 | 7개 경로 SHA256 일치 | 검증 대상 원본·제공 자료·기준 DB 사본의 전후 동일성 |
| DB 검사 | 4개 DB `quick_check=ok`, 외래키 오류 0 | 해당 시점 SQLite 구조 검사 |
| 실제 API 공급가격 예제 | 10매 × 51,069원 = 510,690원 | 시험용 수량에 대한 원문·Decimal·엔진·저장 수식·Excel 일치 |
| 위 공급가격 예제의 입력 변화 | 기준셀 8개, 입력 조건 4개 | 소수 수량·0·누락·음수 처리와 절사 |
| 내수합판 설치 추정 예제 | 기준셀 16개, 가격 변화 1개 | 독립 계산·저장 수식·실제 Excel 재계산과 원복 |

29·33·70은 서로 다른 시험 파일과 검증 경계의 건수다. 하나의 종합 정확도나 현장 성공률을 나타내지 않는다. 406,098행 전수 대조도 데이터 수입의 일치성 검증이며, 모든 품목이 현재 현장에 적용 가능한 가격이라는 뜻은 아니다.

### 기록을 확인한 내부 자료의 종류

공개 문서는 원본 전체 대신 다음 기록의 결과 항목을 요약했다.

- 외부 데이터 독립 대조 결과
- 외부 원장·API 계약·가격정책 시험 결과
- 보존·보안·실행 검증 결과
- 실제 API 계산과 Excel 재계산 결과
- 내수합판 일위대가 계산근거와 검증 보고서

이 자료의 실제 현장 경로, 담당자 정보, 원시 API 응답, 저작물 본문은 제외했다. 공개 데모의 실행 로그를 이 과거 기록을 대체하는 증거로 사용하지 않는다.

## 공개 저장소에서 확인하는 범위

공개 데모는 합성 입력과 임시 자료를 사용한다. 목적은 독자가 네트워크 키나 고객 자료 없이 계산과 실패 조건을 직접 확인하는 것이다.

2026-10-25 로컬 공개 패키지에서 `python -m unittest discover -s tests -v`로 **25개 시험이 통과**했다. 가격 누락·중복, 단위·규격·기간·세금·범위 충돌, 입력값 제한, 가격과 물량 변화, 원본 해시·수식 보존, 독립 계산 불일치 차단을 확인했다. 결과 요약은 [공개 패키지 검사](public-checks.json)에 기록한다.

저장소 [README](../README.md)의 실행 명령과 [tests](../tests/)를 기준으로 재현할 수 있다. GitHub Actions의 결과는 저장소 Actions에서 별도로 확인한다. 과거 로컬 시험 건수를 새 데모의 통과 건수로 제시하지 않는다.

공개 데모의 금액은 프로그램 동작 확인을 위한 값이다. 내수합판 사례에 소개한 과거 공표값과 닮은 입력이 있더라도 최신 API 조회나 현장 견적으로 취급하지 않는다. 데모를 실행해도 실제 현장 내역서나 기준 DB를 편집하지 않는다.

## 검증을 해석하는 기준

| 확인 수준 | 확인할 수 있는 것 | 별도로 필요한 확인 |
|---|---|---|
| 숫자·산식 | 입력과 명시한 계산 규칙에 따른 결과 | 계수와 현장 조건의 적합성 |
| 파일 SHA | 같은 파일 판본인지 여부 | 해당 위치의 숫자를 올바르게 읽었는지 |
| API 성공 | 지정 작업·조회조건의 정상 응답 | 해당 품목의 규격·계약·지역·세금 적용 |
| 저장 Excel 대조 | 수식과 저장값의 대응 | 실제 Excel 재계산과 외부 의존관계 |
| 검사셀 Excel 통과 | 확인한 셀과 입력 변화의 일치 | 미검사 시트·외부링크·전체 도급액 |
| 기존 오류 보존 | 이번 편집에서 새 오류가 생겼는지 | 원본 오류 자체의 해결 |

## 확인된 한계

- 공사구성은 9개 유형·78개 구성요소가 등록되어 있지만, 전 유형의 완결된 자동 도면 물량 산출은 검증되지 않았다.
- PDF 107쪽, DWG 객체 55,336개의 색인 기록은 자료 규모다. 물량 인식 정확도나 자동 설계 완료율이 아니다.
- 과거 조립·내역서 검증 기록에는 기존 수식 오류 17개와 미확인 외부연결 315개가 남아 있다. 별도 내수합판 사례의 한 원본 파일에는 다른 범위인 `#REF!` 14개가 기록되어 있다. 서로 다른 대상의 수치를 섞지 않는다.
- 기존 오류와 미확인 외부연결 때문에 전체 도급액을 일괄 검증했다고 보고할 수 없다. 작업별로 통과한 범위가 다르다.
- API 실제 연결은 선택한 operation·상품·조건 범위다. 모든 상품·지역·조달 계약의 전량 최신 수집을 검증한 것은 아니다.
- 현재가격 적용은 요청 시점의 별도 확인이 필요하다. 2026-10-06 조회 기록으로 이후 날짜의 최신가격을 주장하지 않는다.
- 노임 판본 확인 역시 2026-10-06 기록까지다. 현장 가산·제수당과 간접비가 자동으로 확정되는 것은 아니다.
- 보도블록 모래 두께와 체적 산식의 원문 충돌, DWG 납품판본과 PDF 승인도서의 일치 여부 등 자료 확인 과제가 남아 있다.
- Windows Excel·AutoCAD·Codex 전용 출력 라이브러리에 의존하는 기능은 일반 환경의 합성 데모와 실행 조건이 다르다.
- 정확도 벤치마크, 실무 소요시간 절감률, 비용 절감률, 사용자 규모는 측정하지 않았다.

## 검증에서 얻은 설계 원칙

성공한 계산만 남기면 근거가 없는 단가도 완성된 금액처럼 보일 수 있다. 이 시스템은 가격 누락, 단위 불일치, 최신판본 삭제, 규격 혼동, 시험가격 적용, 지원하지 않는 수식 같은 실패 조건도 검사 대상으로 둔다.

실제 적용에서는 요청 대상과 검증 범위를 먼저 정하고, 그 범위의 독립 계산·수식·Excel 결과가 일치할 때 완료로 보고한다. 확인하지 못한 항목은 결과와 함께 남긴다.
