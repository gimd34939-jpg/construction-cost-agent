# SK AIGEN 지원 포트폴리오

## 프로젝트 한 문장

건축 내역서의 공종 추가 요청을 출처가 연결된 물량·단가·Excel 수정본과 검증 기록으로 이어지게 하는 적산 AI 워크플로를 기획하고, Codex와 협업하여 구현했습니다.

## 문제를 어떻게 정의했는가

처음의 요청은 지붕에 12mm 내수합판 설치 항목을 추가하는 일이었습니다. 실제로는 어느 단가를 사용할지, 자재 공급가와 설치비를 어떻게 구분할지, 다른 시트의 집계를 어떻게 맞출지까지 확인해야 했습니다. 결과 숫자만 받으면 어느 조건이 확인되었고 어느 값이 추정인지 판단하기 어려웠습니다.

그래서 목표를 ‘단가를 빠르게 출력하는 계산기’에서 **근거를 찾아 계산하고, 문서에 반영한 뒤 검증할 수 있는 업무 흐름**으로 구체화했습니다. 중요한 요구는 원본 보존, 규격·판본·단위의 일치, 다른 시트의 연결, 미확정 상태의 표시였습니다.

## 본인이 주도한 부분과 AI의 기여

| 구분 | 확인할 수 있는 역할 |
|---|---|
| 문제·요구 정의 | 추가 공사의 이름과 두께, 지붕 전체 적용, 기존 하지 설치비와의 중복 제외, 원하는 문서 편집 범위를 구체화 |
| 산정 조건 | 가격을 자료에서 조사하고 없으면 추정할 수 있도록 조건 제시. 실제 지시와 작성자 가정을 분리하도록 요구 |
| 결과 피드백 | 다른 시트의 반영 누락을 지적하고 필요한 집계까지 검토하도록 요청 |
| 확장 방향 | 새 독립 단가 연결을 사용한 별도 일위대가 산출로 이어감 |
| Codex 협업 | 코드 구현, 자료·DB 조회, 계산 실행, 문서 생성, 검증과 설명 정리를 보조 |

이는 모든 코드를 직접 타이핑했다는 주장이 아닙니다. AI로 구현을 진행하면서 무엇을 해결해야 하고 어떤 결과를 믿을 수 있는지 구체화한 과정입니다. 팀 규모·고용 이력·사용자 수·코드 기여율은 별도로 주장하지 않습니다.

## 실행하며 바뀐 판단

### 1. 기존 문서의 가격을 그대로 쓰면 편하지만 적용 근거가 약해진다

현행 가격정책은 독립 DB·공식 API를 우선합니다. 내역서에서 관찰한 단가는 신규가격으로 자동 대체하지 않습니다. 자료의 공표일, 실제 조회일, 견적 유효기간도 구별했습니다.

### 2. 한 행이 맞아도 전체 문서가 맞는 것은 아니다

다른 시트 반영에 대한 피드백은 검증 단위를 다시 보게 했습니다. 행 금액, 소계, 상위 직접공사비, 제경비·세금, 전체 도급액은 같은 범위가 아닙니다. 기존 연결 문제까지 해결했다고 과장하는 대신 확인한 범위와 남은 문제를 기록했습니다.

### 3. AI에 확정 숫자를 요구하기보다 부족한 조건을 드러내야 한다

품셈·가격·현장 계수가 부족한 항목은 미완성으로 남깁니다. 내수합판 사례도 외부 공급가격은 확인했지만 지붕 전용 생산성은 확정하지 못했기 때문에 추정 일위대가라고 표시했습니다.
