# SK AIGEN 지원 포트폴리오

## 먼저 볼 내용

**소규모 공사의 추가·변경 견적을 처리할 때, 가격을 찾는 일부터 Excel 집계와 근거 검토까지 이어지는 반복 작업을 줄이고 싶었습니다.** 이 프로젝트에서 제가 주도한 부분은 업무와 포함범위를 정하고, AI가 만든 결과의 누락을 지적하며, 어떤 조건에서 완료라고 판단할지 구체화한 것입니다.

Codex 작업 세션이 자연어 요청을 정리하고 도구를 실행하며, Python 계산 도구가 수치를 처리합니다. 공개 저장소에는 핵심 엔진 소스와 합성 CLI 데모를 제공합니다. [3분 확인 순서](demo-walkthrough.md)에서 결과 → 실행 → 소스 순으로 확인할 수 있습니다.

| 핵심 경험 | 확인할 결과 |
|---|---|
| 업무 문제를 구체적인 조건으로 바꿈 | 12mm 합판 추가, 기존 하지틀 중복 제외, 공급가·설치비 구분 |
| AI 결과를 검토하고 요구를 보완함 | 다른 시트 반영 누락을 지적하고 검증 범위를 행·소계·상위 집계로 나눔 |
| 미확정을 결과에 드러냄 | 가격 누락은 `INCOMPLETE`·전체 금액 `null`, 부분합 별도 |
| 독자가 다시 실행하게 함 | 합성 데모, 실제 엔진 일부 오프라인 시험, 실행 근거 JSON과 결과 그림 |

## 프로젝트 한 문장

소규모 업체가 작은 공사의 견적·추가·변경을 처리할 때 드는 전문 적산 프로그램의 비용과 반복 작업 부담을 줄이고자, 2026년 표준품셈과 가격자료를 직접 DB로 구축하고 공식 API·AI·계산·문서 도구를 연결한 적산 시스템을 만들었습니다.

## 문제를 어떻게 정의했는가

소규모 업체에서는 몇 개 공종의 견적이나 부분 변경만 필요해도 전문 적산 프로그램의 도입·유지 비용과 사용법 학습, 자료 입력에 부담을 느낄 수 있습니다. 저는 작은 작업을 위해 큰 도구를 운영하는 비용이 작업 규모에 비해 비효율적일 수 있다고 보았습니다.

그래서 **데이터를 먼저 구축하고 AI가 그 데이터를 활용해 적산 작업을 수행하는 시스템**을 만들기로 했습니다. Codex로 2026년 표준품셈 전편과 물가·가격자료를 구조화하고, 부족하거나 갱신이 필요한 가격은 인증키를 사용하는 공식 API로 연결했습니다. 사용자는 원하는 작업을 자연어로 설명하고, AI는 DB 조회·규칙 기반 계산·Excel 편집과 검증 도구를 실행하도록 구성했습니다.

내수합판 12mm 설치 항목을 추가하는 사례에서는 공급가와 설치비의 구분, 적절한 단가 선택, 여러 시트의 집계 연결까지 필요했습니다. 이를 통해 결과 금액과 함께 근거·추정·검증 범위를 보여 주는 것이 중요하다고 판단했습니다.

## 어떤 도구의 어떤 업무를 바꾸려 했는가

EBS·EST 같은 전문 적산·내역작성 프로그램이 담당하는 업무 중 소규모 공종의 자료 검색, 단가 조회, 일위대가 산출, Excel 부분 수정과 검토를 대체 대상으로 삼았습니다. 별도 적산 데이터베이스를 AI의 작업 도구로 연결하여 사람이 프로그램 메뉴를 조작하고 자료를 옮겨 적는 과정 일부를 자연어 요청으로 바꾸려 했습니다.

현재는 선택한 범위의 대안을 구현한 단계입니다. 특정 제품을 실제 해지했다거나 전문 소프트웨어의 모든 기능을 교체했다고 설명하지는 않습니다. 제품별 역할과 대체 범위는 [비교 문서](replacement-scope.md)에 정리했습니다.

## 데이터 구축을 구현의 출발점으로 삼음

1. Codex로 2026년 표준품셈 PDF 982쪽 전편의 표·본문·계수·산식·주석을 구조화했습니다.
2. 공종 1,095개, 규격변형 5,987개, 활성 자원투입 11,850개를 원문 위치와 연결했습니다.
3. 노임·기계경비·표준시장단가·자재가격을 정리하고 Excel 검수 원장과 SQLite로 관리했습니다.
4. 확인된 고정계수·명시 산식을 실행기로 연결하고, 부족한 정보와 갱신할 가격을 조달청·오피넷 API로 보완했습니다.
5. AI가 이 자료와 도구를 호출하여 물량·단가 산출, 수정본 생성과 결과 검증을 수행하게 했습니다.

전편 수록과 실행 검증을 구별하여, 근거가 확인된 2,556규격변형·4,539투입과 명시 산식 50레코드를 실행 범위로 연결했습니다. [데이터 구축 과정](data-pipeline.md)과 [사용한 API·키 설정](api-integration.md)에 단계별 내용을 첨부했습니다.

## 본인이 주도한 부분과 AI의 기여

| 구분 | 확인할 수 있는 역할 |
|---|---|
| 문제·요구 정의 | 추가 공사의 이름과 두께, 지붕 전체 적용, 기존 하지 설치비와의 중복 제외, 원하는 문서 편집 범위를 구체화 |
| 데이터 구축 방향 | 표준품셈·가격자료를 AI가 활용할 수 있는 구조로 쌓고 공식 API로 부족 자료를 보완하는 방향 제시 |
| 산정 조건 | 가격을 자료에서 조사하고 없으면 추정할 수 있도록 조건 제시. 실제 지시와 작성자 가정을 분리하도록 요구 |
| 결과 피드백 | 다른 시트의 반영 누락을 지적하고 필요한 집계까지 검토하도록 요청 |
| 확장 방향 | 새 독립 단가 연결을 사용한 별도 일위대가 산출로 이어감 |
| Codex 협업 | 코드 구현, 자료·DB 조회, 계산 실행, 문서 생성, 검증과 설명 정리를 보조 |

이는 모든 코드를 직접 타이핑했다는 주장이 아닙니다. AI로 구현을 진행하면서 무엇을 해결해야 하고 어떤 결과를 믿을 수 있는지 구체화한 과정입니다. 팀 규모·고용 이력·사용자 수·코드 기여율은 별도로 주장하지 않습니다.

## 실행하며 바뀐 판단

### 1. 기존 문서의 가격을 그대로 쓰면 편하지만 적용 근거가 약해진다

현행 가격정책은 독립 DB·공식 API를 우선합니다. 내역서에서 관찰한 단가는 신규가격으로 자동 대체하지 않습니다. 자료의 공표일, 실제 조회일, 견적 유효기간도 구별했습니다.

### 2. 한 행이 맞아도 전체 문서가 맞는 것은 아니다

다른 시트 반영에 대한 피드백은 검증 단위를 다시 보게 했습니다. 행 금액, 소계, 상위 직접공사비, 제경비·세금, 전체 도급액은 같은 범위가 아닙니다. 기존 연결 문제까지 해결했다고 과장하는 대신 확인한 범위와 남은 문제를 기록했습니다.

### 3. AI에 확정 숫자를 요구하기보다 부족한 조건을 드러내야 한다

품셈·가격·현장 계수가 부족한 항목은 미완성으로 남깁니다. 내수합판 사례도 외부 공급가격은 확인했지만 지붕 전용 생산성은 확정하지 못했기 때문에 추정 일위대가라고 표시했습니다.

### 판단과 확인 범위를 함께 보기

| 발견한 문제 | 제가 구체화한 요구·판단 | 구현 대응과 확인 결과 | 남은 범위 |
|---|---|---|---|
| 공급가격만으로 설치비를 말할 수 없음 | 기존 하지틀과 추가 합판을 분리하고 공급·설치 범위를 확인 | 외부 공급가와 작업조·가정으로 별도 1㎡ 일위대가 구성. 과거 사례 기록의 16셀·가격 변화 검사 | 지붕 전용 생산성과 현장 조건 확정 |
| 다른 페이지에 수정이 반영되지 않음 | 필요한 시트와 집계까지 확인하도록 피드백 | 공개 데모에서는 Estimate·Summary 연결값 9셀을 독립 계산과 대조 | 실제 원본 전체의 숨김 행·외부연결·도급액 검증 |
| 자료 부족 상태가 완성 금액처럼 보일 위험 | 확인값·작성자 가정·미확정 조건을 구분 | 누락 가격은 전체 `null`과 부분합으로 분리. 지원하지 않는 공종·범위와 잘못된 가격자료의 파일 생성도 공개 회귀시험으로 차단 | 다양한 공종·현장에 대한 검수 범위 확장 |

이번 공개 검증에서 추가된 입력 차단과 테스트는 포트폴리오 보완 작업의 결과입니다. 이를 과거 실무 사례에서 이미 검증했던 것으로 설명하지 않습니다.

| 비교 조건 | 같은 사람이 두 방식을 쓰는 경우 순서를 바꾸고, 학습 효과·작업 난이도·시험 수를 함께 공개 |

결과를 얻은 뒤에만 비교 조건과 표본 수를 붙여 효과를 설명할 계획입니다.

| 설명할 경험 | 이 프로젝트에서 제시할 내용 |

| 현장에서 풀 문제를 찾음 | 내역서의 가격 근거와 시트 연결을 함께 다뤄야 한다는 요구 |
